# 用例设计

被测系统提供 10 个 REST 接口。本文记录用等价类、边界值、判定表、场景法四类方法设计用例的过程。

## 一、约束

以「新增图书 `POST /api/books`」为例，先列出每个输入项的约束和依据：

| 输入项 | 约束 | 依据 |
|---|---|---|
| title | 不能为空、不能是空白串、长度 ≤ 100 | 接口文档 第 3 条 |
| token | 必须有效；缺失或无效返回 HTTP 401 | 接口文档 第 2 条 |
| author | 可为空；未规定格式与长度 | 接口文档 第 3 条 |
| isbn | 可为空；未规定格式与长度 | 接口文档 第 3 条 |
| price | 必须为数字，精确到 2 位小数 | 接口文档 第 3 条 |
| stock | 必须为非负整数 | 接口文档 第 3 条 |

> 约束没写进文档的（如 isbn 位数），按"任意字符"处理，不臆造规则。

## 四、判定表：借书能否成功

条件：C1 已登录 ｜ C2 库存 ≥ 借阅数 ｜ C3 借阅数合法（1~3）｜ C4 未重复借阅

完整判定表（16 项）：

| 序号 | C1 | C2 | C3 | C4 | 预期结果 |
|---|---|---|---|---|---|
| P1 | 是 | 是 | 是 | 是 | 借书成功 |
| P2 | 是 | 是 | 是 | 否 | 失败：已借未还 |
| P3 | 是 | 是 | 否 | 是 | 失败：数量越界 |
| P4 | 是 | 是 | 否 | 否 | 失败 |
| P5 | 是 | 否 | 是 | 是 | 失败：库存不足 |
| P6 | 是 | 否 | 是 | 否 | 失败 |
| P7 | 是 | 否 | 否 | 是 | 失败 |
| P8 | 是 | 否 | 否 | 否 | 失败 |

## 五、借书 → 还书全流程

**基本流**

1. `GET /api/books/1` → code=0，返回图书数据（stock=4）
2. `POST /api/books/1/borrow {quantity:1}` → code=0，stock 4→3
3. `POST /api/books/1/return {quantity:1}` → code=0，stock 3→4
4. `GET /api/books/1` → stock=4
5. `GET /api/borrows` → 记录 status=returned

**备选流**（借阅超过 3 本）：borrow quantity=4 → code≠0；库存不变；无新增记录

**异常流 1**（未登录借书）：无 token → HTTP 401；库存不变

**异常流 2**（B 归还 A 借的书）：B 调用 return → code≠0；A 的记录仍为未归还；stock 不变

**异常流 3**（连续两次借同一本）：第二次 → code≠0；stock 保持 3；记录只有一条

## 六、用例示例

| 用例编号 | 模块 | 标题 | 优先级 | 步骤 | 预期 |
|---|---|---|---|---|---|
| TC-BORROW-001 | 借阅 | 借阅数大于 3 应被拒 | P1 | 1. 登录取 token；2. `POST /api/books/1/borrow {quantity:4}`；3. 查图书详情；4. 查借阅记录 | code≠0；库存不变；无新增记录 |
| TC-BORROW-002 | 借阅 | 未登录借书应被拒 | P1 | 不带 Authorization 发 borrow | HTTP 401；库存不变 |
| TC-BORROW-003 | 归还 | B 归还 A 的书应被拒 | P1 | 1. A 借书；2. B 调 return；3. 分别查 A/B 记录 | code≠0；A 记录仍 borrowed；stock 不变 |
| TC-04 | 新增 | 书名为空时新增 | P1 | `POST /api/books {title:""}` | code≠0，无 5xx / 无堆栈 |

> 上述用例中有 3 条在实测中失败——被测系统对数量越界、越权归还、空书名均未拦截，详见 [02-缺陷清单.md](02-缺陷清单.md)。
